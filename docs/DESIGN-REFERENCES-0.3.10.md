## 这轮实际改进

1. **网站首页更容易开始使用。** 首屏明确提供个人空间和客户端下载，直接链接日历、助手、网盘和聊天；保留上海与纽约时钟以及原有项目、公告、开发与测试信息。
2. **个人首页可以自己决定。** 选择显示欢迎、今日安排、每日回顾和收藏；勾选并排序收藏。重要提示和管理员状态始终显示。配置按账号保存在服务器，采用版本检查，其他设备的修改不会被旧窗口静默覆盖。
3. **工具更好找。** 按用途分组、即时搜索、星标收藏；所有入口继续按当前权限过滤。取消权限后，收藏不能绕过访问控制。
4. **历史对话属于使用者本人。** 后端按登录账号查询已有记录，分页返回角色、内容与时间；不返回其他账号、调用费用或内部调用 ID。到期已清理的内容不重建，也不为检索消耗模型额度。
5. **管理员首页更可判断。** 顶部集中展示已有巡检的数据盘信息、备份恢复验证、自动任务、今日 AI 用量；报告数据标明检查时间，缺失数据、旧备份和额度接近上限明确提示。
6. **多设备保持连贯。** 网页与已安装客户端共用更新后的页面；手机提供窄屏弹窗和触控按钮，桌面保留并列信息。浅色、深色及跟随时间偏好继续生效。

## 继续优化的顺序

| 优先级 | 后续改进 | 价值与所需条件 |
| --- | --- | --- |
| 下一轮 | 独立 AI 会话、会话标题与归档 | 目前助手是单条连续记录；会话分组可避免工作、学习、管理内容混在一起，需同时定义上下文与额度计算规则 |
| 下一轮 | 统一操作结果与失败重试入口 | 让日程、下载、管理任务的错误均能定位到相应记录，AI 重试保留费用确认 |
| 下一轮 | 资源历史曲线与告警确认 | 当前状态卡片引用已有检查报告；CPU、内存和磁盘趋势需增加有保存期限的定期采样，明确采样成本和缺失区间 |
| 后续 | 异地加密备份与恢复演练 | 目前备份在服务器本机；需要确定另一台设备或对象存储、凭据和容量上限 |
| 后续 | 邮件、外部日历、任务审批 | 需要用户选择服务商并完成授权；邮件发送及其他外部写操作应有明确的确认记录 |
| 后续 | 原生客户端签名与系统更新 | 桌面签名、iOS TestFlight/App Store 需要相应开发者账号和签名材料；保持服务器页面更新与安装包版本独立 |

这些是后续工作建议，不表示这轮已经接入上述外部服务或原生发布渠道。

## 验证重点

- 管理信息仅管理员可见；成员收藏与客户端自定义不产生权限提升。
- 偏好按账号隔离，重复设备编辑返回冲突；首页隐藏设置不能移除重要提示。
- 对话检索与分页只返回本人记录，使用北京时间筛选，所有响应沿用 API 禁止缓存策略。
- 手机 360px、390px 和桌面布局；对话检索、偏好弹窗和系统深浅色。
- 日程离线缓存继续只保存明确允许的日程副本，不加入历史对话或管理数据。
